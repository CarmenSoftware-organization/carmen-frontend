## Decided
2026-11-13 ผู้ใช้สั่งบนหน้า Inventory Period ของ System Admin: วันที่ของงวดห้ามแก้ไข และการปิดงวดต้องสร้างงวดถัดไปพร้อมวันที่เอง โดยมีงวดเปิดล่วงหน้าเสมอ 12 เดือน

- การปิดงวดเติมงวดเปิด (open + locked) กลับให้ครบ 12 ใน transaction เดียวกับการปิด ปิดกับเติมจึงสำเร็จหรือล้มเหลวพร้อมกัน และใช้ได้กับทุก client
- วันที่ของงวดมาจากตัวเติมงวดจุดเดียว: วันที่ 1 ถึงวันสุดท้ายของเดือน เที่ยงคืน UTC ต่อจากงวดเปิดงวดสุดท้ายทีละเดือน
- API ปฏิเสธการแก้วันเริ่ม วันสิ้นสุด ปีบัญชี เดือนบัญชี แต่ค่าที่เท่าเดิมผ่านได้ (เทียบเป็นจุดเวลา ไม่เทียบ string) เพื่อไม่ทำ client ที่ส่งทั้งก้อนกลับมาพัง
- สร้างงวดด้วยมือได้เฉพาะตอน BU ยังไม่มีงวดเลย
- หน้าเว็บเป็นแบบดูอย่างเดียว ปุ่ม "เติมรอบ" คงไว้สำหรับ BU ใหม่และ BU ที่มีไม่ถึง 12 งวด

## Tried and ruled out
- เปิดทีละงวดเดียว (งวดถัดไปเกิดตอนปิดเท่านั้น): เอกสารรับเข้า (GRN, Stock In) ที่ลงวันที่เดือนถัดไปจะถูกปฏิเสธขณะเดือนปัจจุบันยังไม่ปิด เพราะด่านวันที่ต้องเจองวดเปิดที่ครอบวันนั้น ผู้ใช้เลือกให้มีงวดล่วงหน้า
- ให้หน้าเว็บยิงเติมงวดต่อหลังปิดงวดสำเร็จ: ไม่ atomic และ client อื่นที่ปิดงวดจะไม่เติมให้
- cronjob เติมงวด: มีช่วงที่งวดไม่ครบ

## Watch out
- ในเครื่อง มีแค่ gateway รันที่ :4000 ส่วน micro-business ไม่ได้รัน gateway ต่อไป dev ร่วมที่เป็นโค้ดที่ deploy แล้ว ยิง PATCH/POST ทดสอบด่านใหม่ก่อน deploy = แก้ข้อมูลร่วมจริงด้วยโค้ดเก่า
- deploy backend ก่อน frontend
- ณ วันที่บันทึก ยังไม่เคยปิดงวดจริงเพื่อดูงวดใหม่เกิด และยังไม่เคยยิงด่าน API จริง ยืนยันด้วย spec เท่านั้น
- spec ที่ mock transaction ของการปิดงวดต้องมี findMany ของตารางงวด ไม่งั้นแดง
