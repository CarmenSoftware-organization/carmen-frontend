02

The operating problem

Cost of goods is a hotel's second-largest line and its least instrumented one.

  • Buying runs on spreadsheets, email and chat. The approval exists, but only in someone's inbox.
  • Every property invents its own process. Group management cannot compare what it cannot standardise.
  • Stock counts happen on paper and reconcile late, if at all — so variance is discovered a month after it was created.
  • The systems that do exist don't meet. Purchasing, receiving and the accounting ledger are three separate stories about the same money.
03

What Carmen Blue is

One system from requisition to receipt to stock ledger, across every property in a group.

Procurement

Purchase requests and templates, purchase orders, goods received notes, credit notes, an approval inbox.

Inventory

Physical counts, spot checks, adjustments, the transaction ledger, period end.

Store operations

Store requisitions, wastage reporting, stock replenishment.

Vendors

Vendor master, price lists and templates, requests for pricing.

Products & recipes

Product master and categories, recipes with ingredient breakdown, cuisines, equipment.

Administration

Users, roles, workflow designer, running codes, notification templates, print forms, external interfaces.

Every operational document carries a server-written activity trail: who did what, and when.

09

Multi-tenancy

Isolation is structural, not a filter someone remembered to write.

A shared platform schema holds identity, roles and subscriptions. Each business unit's operational data lives in its own schema.

  • Cross-tenant leakage would take a schema-level mistake — not a forgotten condition in a query.
  • One property can be backed up, restored or migrated without touching anyone else.
  • Group reporting reads across a cluster under the caller's entitlements, without pooling tenants into one table.
  • A single-tenant deployment is the same product, not a fork.
10

Security & identity

The credential that matters is never written down.

  • The access token lives in memory only. Reading browser storage yields nothing usable.
  • The refresh token is the only stored credential, and revoking it is a server-side operation — signing out ends the session for real.
  • Identity is delegated to a dedicated provider. Carmen Blue never stores a password.
  • Permissions are scoped to cluster and business unit. The role says what; the scope says where.
  • Integration secrets are encrypted at rest and never returned to the browser. An administrator can replace a secret, not read it back.
11

Engineering judgement

Two languages, each where it pays for itself.

WhereWhatWhy there
TypeScript API, services and the web client One type system from database to screen. A change to a document shape fails at compile time, not in front of a user.
Go Report rendering and scheduled jobs CPU-bound and bursty. A month-end report run must never slow down a kitchen raising a requisition — separated by process and by language.

Nothing is in this stack because it is new.

12

Scale & cost posture

The tier every user touches has no servers to pay for.

  • The web tier does not scale — it is files. Static assets on a CDN absorb user growth without additional servers.
  • The API gateway holds no session state, so it scales horizontally behind a load balancer.
  • Scheduled jobs coordinate through a distributed lock, so replicas run safely: exactly one instance executes each job.
  • Abusive traffic is rejected at the gateway, before it reaches a domain service or the database.
  • Per-tenant schemas are a natural sharding boundary if a large group ever needs dedicated database capacity.
